# Legacy reconciliation

Preserve first, reconcile second. Scan existing instructions, engineering docs, commands, workflow files, and generated markers before proposing a structure.

Create a Decision Group only when multiple observations depend on the same explicit root choice. Each group includes:

- stable ID and original sourced evidence;
- recommended choice and why;
- viable alternatives;
- risk and affected files;
- dependent actions;
- state: unresolved, accepted, rejected, or deferred.

Do not group conflicts merely because they appear nearby. Do not resolve semantic contradictions from filename preference, majority count, or package scripts alone. Ask one focused question when evidence cannot establish authority.

Human-authored files and managed sections whose current SHA-256 differs from the manifest are `manual-drift`. Never overwrite them. Present preserve/reference, adopt as authority, move-after-confirmation, or remove-after-confirmation alternatives. If the user defers a group, keep independent actions and remove dependent actions from the plan.
