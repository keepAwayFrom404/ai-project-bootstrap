# Progressive loading

- Keep a small mandatory foundation with scope, authorization, safety and maintainability constraints.
- Use task-based routing with explicit read triggers: setup only when starting services, troubleshooting only on failure, domain sections only for affected work.
- Links locate authority; do not recursively load every linked document. Reuse unchanged rules within a session, refreshing when relevant content changes.
- Maintain one authority per concern. Reuse existing paths; separate current rules from historical evidence, and never use summaries to replace a relevant business contract.
- Record section-level destinations in prose when useful; the Registry authority column remains a repository-relative file path with an optional validated chapter fragment, never a tool command.
- This is a reading contract, not a runtime loader. Do not claim that a host unloads already-read context or enforces a token budget.
